- **Two creation paths, same result.**
  - A model that can make images (Muse) creates a style-matched image from a prompt template, saves it into the project, and `lib import` turns it into a vector asset.
  - A model that cannot (Claude Code, Sonnet) draws the asset as code: declarative parts, parameters, costume pieces.
  - Both produce the same asset format and go into the same library.
- **Hybrid look.**
  - Vector: everything near, moving or touching people (vehicles, buildings, near plants, props).
  - Painted images: allowed only for FAR background layers (sky / far / mid plates).

  - Weather is parametric.

## The asset format (one folder per asset)
```
library/<type>/<id>/
  asset.json    {id, type, name, tags[], doc, size, anchors{}, parts[] | parts_file, motion{}, source{kind: image|code, prompt, files}, project, status: draft|approved, created}
  art.svg       optional: the vector picture (for humans and for re-import)
  source/       optional: the original image(s) + prompt.txt (image path)
  preview.png   generated by `lib preview`
```
Types:
- `props`, `vehicles`, `buildings`, `plants` (rigid or with moving parts);
- `costumes` (pieces worn by people);
- `places` (story places: kit or compose specs);
- `plates` (painted far backgrounds, layered);
- `weather` (parameter presets);
- `characters` (cast looks: preset + costume pieces).

Coordinates are those of the engine's Drawing parts: (0,0) = where the thing stands (bottom centre), y up is negative, a man is ~260 units tall. Engine assets (code-drawn props, vehicles, presets, sets, kit styles) are listed in the index as `builtin` so `lib search` finds everything in one place.
